Two different jobs, so two tools

A shoe in size 42 / Black is a different item on the shelf, with its own stock and barcode. A Paw-er Drink with Red Bull + Mango is one menu item made to order: the base and flavour are choices, not separate items. Putting both through one "variant" system is why the last version felt wrong.

Recommended final structure

Product Variants (retail: size / colour / design → stock items) + Option Groups (menu: base, flavour, add-ons → choices on one item) an option can open another group

The Design layer from the last round stays useful for retail items (a floral shirt in M is a real stock item). The Paw-er Drink moves off variants and onto option groups.

A · Option Groups (modifiers)

The way restaurant POS systems handle this. You build reusable groups ("Drink base", "Flavour", "Tea add-ons") with a rule: pick exactly 1, pick up to N or optional. Attach groups to any product. Each option can add a price, use a stock item, and open a follow-up group, so you can add layers later.

C · Bundle slots

The product is a set of slots, and each slot is filled with a real product from the catalogue: Base slot (Red Bull can, Soda can), Flavour slot (syrup bottles). Stock is always exact, which suits meal deals. Simple menu choices like "less sugar" have to become products, though.
