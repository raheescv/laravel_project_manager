What the port actually changes
  • Tokens — one replaced :root block in src/assets/app.css (plus its dark twin). Every screen already reads these, so bills, meals, statements and the result screens follow for free.
  • Two new tokens — --card-ink / --card-gloss, so a light card face (Amber) is possible; today the card text is a hard-coded white.
  • Boxed fields — .pp-form + .pp-boxed for the four form screens (sign in, forgot, set password, change password). Data rows keep the grouped-list look.
  • The canteen panel — .pp-art with the inline illustration replaces today's dark gradient sign-in panel, and becomes the phone sign-in header.
  • Type — headings go to Figtree 800 at −.035em. Same font, already loaded.
Two things your mockup implies that I did not assume
  • “Send sign-in code” — your image is a passwordless e-mail code. The portal signs in with mobile/email + password today, and the code flow is a backend change (codes, expiry, rate limits, e-mail template). I kept the password form. Say the word and I will scope the code flow separately.
  • The accent — brick #B94420 is the default here, but --accent is still fed by the school's theme colour from /api/v1/parent/school. Try the swatches above: the cream and amber survive any school colour. If Newrest should always be brick regardless, I pin it instead.
