Tablet chrome — the rail/pane corner

Today the side-rail is a floating rounded card (14pt margin, 26pt radius, a heavy shadow) while the content beside it is a docked flush pane with square corners. Two different idioms meeting on one edge is what makes that top-left corner read as a mistake — the rail's rounded shoulder cuts into a pane that was drawn as if the rail weren't there. Four ways out, all on the real Emerald & Gold tokens.

Direction ARecommended

Docked rail — one idiom, edge to edge

The rail stops floating. It loses its margin, its borderRadius: 26 and its shadow, and runs the full height of the window; the panes dock against it on a hairline. There is no corner left to resolve — the awkward shoulder only existed because a rounded card was parked against a square pane.

It is also the direction the app is already moving in: New Sale's two panes were just made full-bleed for exactly this reason, and the rail is the last floating thing left. As a bonus the 14pt margin and the 26pt radius come back as usable content width on both sides.

Gains
  • Corner problem disappears entirely
  • ~28pt of width back
  • Matches the docked panes on New Sale
Costs
  • Loses the "premium floating card" flourish
  • Status-bar ink must flip over the rail
Code
  • AstraSideRail: drop margin, radius, shadow; add a right hairline
  • One widget touched
Direction B

Inset canvas — the rail is the backdrop

The rail is flush and dark all the way to the edges, and everything to its right lifts into a single rounded surface floating on it with an even gutter. The corner now reads as deliberate because the gutter is continuous on all four sides — nothing is cut into anything.

This is the most "designed" of the four and the one that looks most like a modern desktop sidebar. The cost is that the dark rail colour becomes the window's backdrop, which is a stronger look than the cream canvas the app has now.

Gains
  • Most polished; corner is a feature, not a patch
  • Content reads as one object
Costs
  • Dark backdrop is a bigger visual change
  • Loses ~20pt to the gutter
Code
  • Rail flush as in A
  • Shell wraps the content Row in a rounded, clipped container
Direction C

Two peers — make the content float too

Keep the floating rail exactly as it is, and give the content the same inset, the same radius and the same shadow. The two shapes stop arguing because they are the same shape. This is the smallest change in character — nothing about the rail moves — but it is the most expensive in screen.

It also pulls against the New Sale work, where the panes were just docked to the edges to win back the space this direction spends on margin.

Gains
  • Keeps the floating look the app has today
  • Consistent, calm
Costs
  • Spends the most width on margin (~40pt)
  • Contradicts New Sale's docked panes
Code
  • TabletPane gains margin + radius + shadow
  • Every tablet screen inherits it
Direction D

Unified shell — one card, split inside

Rail and content live in one rounded card, split internally by a hairline, with the canvas framing the whole app. Only the outer corners are rounded, so — as with A — there is no interior corner to get wrong, but the window keeps a soft, contained silhouette.

The catch is the frame: a uniform inset all the way round costs width on both sides and pushes the status bar off the app surface, which reads oddly on a device that is genuinely full-screen.

Gains
  • Soft silhouette, no interior corner
  • Reads as one object
Costs
  • Frame costs width on both sides
  • Status bar floats off the surface
Code
  • Shell wraps rail + panes in one clipped rounded container
  • Rail flush inside it
