The defects that were real

  • Pagination could lock up permanently. _loadMore() set its in-flight flag then early-returned past the reset when filters changed mid-fetch. Infinite scroll then died for the life of the screen. It had been copy-pasted into three screens. Now one shared PaginatedListCubit with a regression test.
  • Money drifted from the server. Every money column in the Laravel schema is decimal(16,2) and the sale totals are generated columns, so MySQL rounds each intermediate. The app summed unrounded doubles and rounded once at the end — enough for a settled ticket to show a phantom balance. Now rounded at the same points via round2(), with 32 tests.
  • Three routes crashed on restore. state.extra as Sale and friends, with extra being null after a process kill. Now guarded by a route redirect.
  • Wrong currency on the till. A hardcoded $ in the line-discount label.
  • A real phone number as a "blank" sentinel, which wiped that customer's number on edit.
  • Nine leaked TextEditingControllers, one pair per sheet-open.
  • A fifth of the test suite was silently disabled — the harness never got PosSettingsCubit, so 15 tests threw ProviderNotFoundException, including the only test covering checkout.

Conventions that came out of it

Migrating a cubit: move the fields into an Equatable state, replace assignments with emit(state.copyWith(…)), and leave a forwarding getter per field so existing readers compile unchanged. CartCubit had 109 read sites across 6 files — none needed touching.

Watch for state that depends on the outside world: ThemeCubit had to take platformIsDark as a real field, because with an Equatable state an emit that changes nothing rebuilds nothing — and an OS dark-mode flip has to re-skin the app.

Splitting a large screen: a private extension in a part file can hold the widget-builders with zero call-site changes — members stay library-private and invocation stays implicit. Eight files came under 900 lines this way without touching a widget tree.

Lazy lists inside a card: DecoratedSliver cannot express AstraCard's Glass skin (a BackdropFilter inside a ClipRRect). Rather than fork card rendering by skin, the Reports card fills its pane and scrolls its rows internally — lazy, and identical under all five presets.

Follow-ups — now also done

Rebuild scoping. New Sale and Cart no longer watch a whole cubit from the top of build. Paging the catalog appends 20 products without rebuilding the cart header or bar, and editing the ticket no longer rebuilds the product grid. Eight BlocBuilders and seven BlocSelector/context.select sites, from zero.

Crash reporting has a destination. CrashReporter now POSTs to POST /api/v1/client-error, added on the Laravel side. It files into the existing api_logs table (endpoint client/crash, status failed) so no migration is needed, and it is rate-limited to 20/minute so a crash loop on one till cannot flood the log. The upload is fire-and-forget and completely silent — a failure there must never surface to a cashier, and must not re-enter the reporter.

Deliberately not done — and why

Converting the remaining Widget _x() methods to StatelessWidgets. This was on the list as a performance fix, and it no longer is. The two changes above removed the reason: every long list is now lazy, so an item builder only runs for visible rows, and the screen chrome is scoped so it no longer rebuilds on unrelated state. What is left is a real but ordinary readability preference, worth ~120 bespoke extractions across seven screens with no test that would catch a layout regression.

File size — the concrete complaint — was already solved by the part splits: no file in lib/ exceeds 900 lines. Extract the widget-methods of whichever screen you are already editing; do not run it as a project.
